# Roadmap – Update 5: Video Player

A fifth shelf type, **Video**, for films, episodes and clips the user already has on their phone. It works like the music shelf: pick files, they're copied into the app, and the shelf opens in a layout made for them, with a proper player.

**Scope and copyright:** the same as the readers and music. EverShelf only plays files the user picks on their own device. It never searches, streams or downloads from websites.

---

## Background: video formats

| Format | Container | Android (ExoPlayer) | iOS (AVPlayer) | First version? |
|---|---|---|---|---|
| **.mp4 / .m4v** | MP4 (`ftyp` box) | ✅ | ✅ | ✅ |
| **.mov** | QuickTime (same box structure as MP4) | ✅ (H.264/HEVC) | ✅ | ✅ |
| **.3gp** | MP4-style boxes | ✅ | ✅ | ✅ |
| **.mkv** | Matroska (EBML, `1A 45 DF A3`) | ✅ | ❌ | ✅ Android only, iOS explains why not |
| **.webm** | Matroska subset | ✅ | ❌ | ✅ Android only, iOS explains why not |
| **.avi / .wmv / .flv** | old containers | ❌ / partly | ❌ | ❌ Not supported; the import says so |

* An **audio-only .mp4** is still a song (music shelf). An .mp4 with an enabled `vide` track is a video. `readMp4` already tells them apart, so the same check decides which shelf a file fits.
* Codecs inside a container (H.264, HEVC, VP9, AV1…) are decoded by the phone. A file the phone can't decode shows a clear "can't play this video" message in the player rather than a black screen.

**What Expo gives us (SDK 58):**

* `expo-video` is **included in Expo Go**. `useVideoPlayer(source, setup)` + `<VideoView>` with native controls, fullscreen (`fullscreenOptions`, with landscape orientation), `playbackRate`, `seekBy`, `timeUpdate` / `playToEnd` / `statusChange` events, embedded subtitle and audio tracks, and `keepScreenOnWhilePlaying`.
* `player.generateThumbnailsAsync(times)` makes thumbnails. They're native image references, so `expo-image-manipulator` (also in Expo Go) renders one to a JPEG file that becomes the item's cover. (`expo-video-thumbnails` is deprecated.)
* **Background audio and picture-in-picture** need the `expo-video` config plugin options `supportsBackgroundPlayback` / `supportsPictureInPicture`, so they need a **new native build** (Phase 6). Everything before that is testable in Expo Go.

---

## Decisions (settled)

1. **One video = one item**, like songs. Its title is the item title; extra info (year, description, series) are tags, so search, sort, tags, selection, Move and Delete keep working.
2. **A new `video` shelf kind and `video` file kind.** `canHold` stays the single rule: videos only import onto video shelves, songs never do.
3. **Movies and Anime stay `collection` shelves** after the update: nothing is converted behind the user's back. Since they hold no files, the shelf editor already lets the user switch them to **Video** in one tap. New installs get a built-in **Videos** shelf.
4. **Files are copied natively** into `books/<itemId>/video.<ext>` (next to song files), never read into memory. Films are often 1–4 GB.
5. **Cover = a frame from the video**, taken at import (about 10% in, at most 30 s), unless the MP4 has its own cover art.
6. **Video and music don't play at the same time.** Starting a video pauses the music player.
7. **Watching progress reuses `playback_progress`** (position, play count, last played), plus a `finished_at` for "Watched".

---

## Phase 0 – Prep ✅

1. New branch `feature/video` (from `feature/shelf-types`, which holds the music work).
2. `npx expo install expo-video expo-image-manipulator`. The `expo-video` plugin is in `app.json` with no options yet (Phase 6 adds them).
3. Test files (real ones, since video can't be generated by a script): a short phone-camera .mp4 and .mov, a film-length .mp4 (1–2 h) for seeking and resume, an .mkv with subtitles, a .webm, an audio-only .mp4 (must go to music), an .avi (must be refused) and a file renamed to .mp4 that isn't one.

## Phase 1 – Shelf type and storage ✅

* `ShelfKind` and `FileKind` gain `'video'`; `SHELF_KINDS` lists it, so the **shelf editor shows a "Video" button** with a one-line hint of the formats.
* **Migration V11**: a `videos` table (`item_id`, `file_name`, `format`, `duration_ms`, `width`, `height`), and `finished_at` on `playback_progress` (added only if missing, so a half-applied upgrade can run again).
* `SELECT_FILE_KINDS` includes videos, so the misplaced-item banner, Move targets and type changes all know about them.
* New installs get a **Videos** shelf. Translations for the type in English and Chinese.

## Phase 2 – Import

1. `detectFormat` learns video extensions and MIME types; `sniffVideo` knows MP4/MOV boxes and Matroska's EBML header. For any MP4-style file the `moov` box decides: video track → video, sound only → song.
2. `readVideo` (pure, with tests): container format, length, width and height (from `tkhd`), and MP4 tags (title, year, description, cover art). Matroska's length comes from the player on first play.
3. `importVideos.ts`, like `importSongs.ts`: several files at once (a season), files that aren't videos are skipped and listed, a free-space check, progress ("Copying 2 of 8"), and clean-up on failure.
4. **iOS** refuses .mkv/.webm at import with *"iPhones can't play .mkv videos. Convert it to .mp4 first."*
5. A thumbnail becomes the cover (decision 5). If it fails, the video still imports with a plain cover.
6. The import screen lists the videos (title, length, resolution) and lets the user fix titles before saving.

## Phase 3 – Video shelf layout

* `VideoShelf`: wide 16:9 cards (thumbnail, title, length, a progress bar along the bottom, a ✓ when watched), or rows in list view.
* **"Continue watching"** at the top: started, not finished, most recent first.
* Tapping a video plays it. Long-press selects; with one video selected the bar has **Details**. Entries without a file open their details.
* The details screen gets a **Play / Resume** button and shows length and resolution.

## Phase 4 – Player

* `src/app/watch/[itemId].tsx`: black screen, `VideoView` with native controls, fullscreen (rotates to landscape), title in the header.
* **Resume**: start where the user stopped (unless within 10 s of the start or the end). Save the position every 5 s and when leaving. At the end: mark watched, count a play, and next time start from the beginning.
* The music player pauses when a video starts; the mini player hides on the video screen.
* A file the phone can't decode shows *"This phone can't play this video"* instead of a black screen.

**After Phase 4, video works in Expo Go** while the app is open.

## Phase 5 – Watching comfort

* **Speed** (0.5×–2×), **skip ±10 s** buttons and **double-tap left/right to skip**, as in other players.
* **Next up**: at the end of a video, offer the next one on the shelf (in the shelf's sort order) with a 5-second countdown; a setting turns autoplay off.
* **Subtitles and audio tracks**: pick from the file's embedded tracks (`availableSubtitleTracks`, `availableAudioTracks`), and remember the choice per video.
* **Mark watched / unwatched** from the selection bar and the details screen.
* *(Optional)* External `.srt` files next to the video: parse to cues (a pure function with tests) and draw them over the player ourselves, since `expo-video` only shows embedded tracks.

## Phase 6 – Background audio and picture-in-picture (needs a dev build)

1. `expo-video` plugin options: `supportsBackgroundPlayback: true`, `supportsPictureInPicture: true`. **Never edit `ios/` or `android/` by hand.**
2. `allowsPictureInPicture` and `startsPictureInPictureAutomatically` on the `VideoView`, so going home keeps the video in a small window.
3. Optional "keep playing sound in the background" (`staysActiveInBackground`, `showNowPlayingNotification`) for talks and concerts.
4. Build with `npx eas-cli@latest build --profile development` and test on real phones: PiP on Android 12+ and iOS, a call during playback, Bluetooth headphones, and audio mixing with the music player.

## Phase 7 – Backup, testing and release

1. **Backup**: video files are far too big for the backup. Back up items, tags, video info and watching progress, and say clearly that the video files aren't included.
2. **Test**: upgrade V10 → V11 on a database with novels, comics, songs and a mixed shelf; importing a video onto every other kind of shelf and a song onto a video shelf; changing Movies to Video; a 4 GB file and low storage; a 2-hour film resumed after closing the app; .mkv on iOS.
3. Translations for everything new, in English and Simplified Chinese.
4. **Release**: `expo-video` and `expo-image-manipulator` are native modules, so this needs **a new EAS build** for both stores. JS-only fixes after that can go out with `eas update`.

## Later ideas

* **Series**: group a shelf by a "Series" tag with season/episode order (`S01E03` in file names).
* Import a whole folder (`Directory.pickDirectoryAsync` on Android).
* Chromecast / AirPlay (`VideoAirPlayButton` exists on iOS).
* "Open with EverShelf" for video files from the file manager.

---

### Notes

* As with the earlier roadmaps, each phase ends in a working app and a commit.
* Keep parsing (format sniffing, MP4/MOV boxes, EBML header, SRT later) in pure functions with Jest tests on generated bytes.
* The main risks are **file size** (always copy natively, check free space first) and **codec support differing by phone** (handled with a clear player error, not at import, since only the phone knows what it can decode).
